# 留声 · Liusheng Player

一个简洁的音乐播放器。基于 [CharlesPikachu/musicsquare](https://github.com/CharlesPikachu/musicsquare) 改造，保留多音源搜索、歌词、收藏和歌单管理，重新设计为浅色静态界面。

## 功能

- 网易云、QQ、酷我、JOOX 和酷狗音源搜索与播放，默认全部勾选。手动搜索固定每源最多读取 5 个候选，不提供数量选择、加载更多或滚动追加；未搜索时不显示结果计数。搜索结果先以最多 4 路并发检查播放地址及浏览器能否加载音频，只显示通过检查的歌曲，并显示已过滤数量；新搜索会取消旧检查，不打断当前播放。
- 统一使用本地内嵌的 Lucide 线条图标；音质标签提供中文名称和说明，不再将未知码率一律标为 320K。
- 收藏搜索、歌名/歌手排序、收藏 JSON 导出及清空（二次确认）。清空收藏不删除自建歌单，也不中断当前播放。
- 自建歌单支持按当前歌单的歌名、歌手、专辑搜索；筛选不改变原歌单与播放顺序。搜索结果页支持清空，并取消未完成的搜索，防止旧结果回填。
- 歌曲搜索和“我的音乐”可分别收起、展开，自动记住状态；收起后播放器使用腾出的空间。
- 播放时自动补全歌词：优先原平台，再匹配同歌名、歌手和版本的备用歌词；支持纯文本和滚动歌词，后台查询不阻塞播放。
- 播放器右上角可切换「纯净模式」：大字居中歌词，保留进度、切歌和音量；点击退出或按 Esc 返回，刷新后记住显示模式。
- JSON 歌单导入导出、自建歌单、一键同步收藏。导入入口提供网易云 / QQ 取链接指引和 JSON 文件指引、格式示例下载、5 MB 文件校验及预览确认。
- 网易云、QQ 链接及 JSON 文件导入统一显示总数、已完成和剩余数量，电脑最多 12 路、触屏设备最多 8 路静音检查开头及中段，跨源选择最多同时处理 6 首。所有歌曲先按去除版本后缀的歌名跨网易云、QQ、酷我、JOOX、酷狗查找明确的原唱标注，不把导入歌手、搜索排名或高音质当作原唱依据。标题中的“原唱／翻自／cover”标注或已保存的明确原唱信息可用于识别；搜索结果原唱标注冲突或缺失时不猜，保留可播版本并标记“原唱待确认”。确认后优先选择原唱录音室版本，即使导入的翻唱能播放、音质更高也不优先。默认勾选跨源最高可播音质，在原唱版本内从高到低试播；取消音质优选仍先识别原唱，确认原唱可播即保留。原唱候选不可播时保留其他可播版本并说明。无损试播成功即取消其他候选查询，同档最多 2 路并行试播；高音质失败才降级，不把未知音质冒充高码率。选择的实际可播档位会保存。
- 导入完成显示保留原曲、择优替换、已移除和未检查数量；保留原曲也可能已升级为同一歌曲 ID 的更高可播音质。未找到可播替代的歌曲不再导入，并移除收藏或歌单中对应的失败原曲；停止检查时保留已通过结果，尚未检查的条目保留并标记“未检查”。刷新时自动清理旧版本已经标记“待修复”的条目，其他收藏和歌单内容保持原样。重复导入可替换原条目而不累加重复的替代曲。检查不改动左侧搜索或当前播放；浏览器阻止试播时明确提示并保留原歌单。
- 默认随机播放，记住模式、音量、歌曲及播放位置；浏览器限制自动播放时需点击播放。
- 桌面、平板和手机布局；手机端固定页面比例，限制手势缩放，触控设备的输入控件至少使用 16px 字号，避免聚焦时自动放大；去除粒子、水波纹和闪动背景。
- 音源连接失败会明确提示；短暂网络错误自动重试一次。播放失败后可直接点击播放刷新地址并保留进度，解码失败时优先使用兼容音质。

## GitHub Pages

将本仓库上传到 GitHub，在 **Settings → Pages → Deploy from a branch** 选择 `main` 分支的 `/(root)`。

前端为单个 `index.html`，无需 npm 安装或构建。`.nojekyll` 用于直接发布静态文件。

收藏、歌单和播放记录仅保存在当前浏览器。代码仓库不包含个人收藏或音频文件；换设备时通过 JSON 导出、导入迁移。

## 音源与代理

沿用原项目的公开接口：网易云使用 qijieya Meting，QQ 使用 tang music API，酷我使用 OIAPI。GitHub Pages 上的 QQ 搜索和详情请求默认直接访问同一个允许跨域的 QQ 接口；本地运行时使用 `server.py` 的同源代理。

代理不会提供平台未返回的播放地址，歌曲是否可播放仍取决于音源。QQ 导入条目缺少标识时，按歌名和歌手匹配，避免直接播放错误版本。

播放地址统一使用 HTTPS，临时地址最多缓存 10 分钟。酷我收藏每次刷新地址时先按歌曲 ID、歌名和歌手重新定位，避免搜索排序变化后播放其他歌曲。QQ 没有返回播放地址时明确报错，不会把空地址算作成功。

如果多个音源同时连接失败，尤其浏览器显示 `ERR_CONNECTION_CLOSED`，请检查系统代理或网络路由：网页能打开不代表音乐 API 和 CDN 可达。可以按实际网络情况为音乐域名设置直连例外；不需要关闭 HTTPS 校验或降低浏览器安全设置。

酷我歌词使用官方歌曲 ID 接口，缺失时尝试网易云和 QQ 的匹配歌词。补全歌词不会替换播放音源；纯文本歌词会明确标注没有时间轴。最近 80 首歌词保存在当前浏览器的独立缓存中，大小限制为约 18 万字符；纯音乐或接口没有返回的歌词仍可能无法补齐。

QQ 公开歌单支持直接粘贴手机分享的 `i2.y.qq.com/n3/other/pages/details/playlist.html?id=...` 链接或整段分享文字，也支持原有电脑地址。线上未配置代理时，通过现有 qijieya Meting 的 `server=tencent&type=playlist` 接口读取列表，无需登录或另外部署服务；只发送歌单 ID，去除账号及跟踪参数。返回列表校验成功后合并到自建歌单，可勾选同时加入收藏。线上接口未提供歌单名称和总数，按歌单 ID 命名并显示实际读取数量。

网易云完整歌单网址和 QQ 公开歌单网址可通过现有 Meting 接口读取。网易云 `163cn.tv` 短链接由留声歌单解析服务在服务器端展开，再按平台完整歌曲 ID 补齐列表；解析服务不保存歌单或音频，只允许播放器与本地页面跨域读取。整段读取最多等待 35 秒，失败明确显示原因。已配置的线上自定义歌单服务在 8 秒内无响应或返回网络错误时，自动改用备用解析服务；本地导入仍使用本地服务。线上也可在“音源设置”填写自己的 HTTPS 代理地址，接口约定与本仓库的 `server.py` 一致：

- `GET /api/qq?msg=歌名&mid=可选的QQ标识`：查询 QQ 搜索结果或歌曲详情。
- `GET /api/playlist?url=完整歌单链接或分享文字`：返回本站可导入的歌单 JSON。网易云支持整段“分享歌单: … https://163cn.tv/… (@网易云音乐)”：服务端只在网易云域名内展开短链接，读取全部歌曲 ID 并按原顺序分批补齐资料；未能读全时明确显示警告。

未配置代理时，线上可使用搜索、播放、网易云 / QQ 公开歌单链接导入和 JSON 歌单导入导出。代理需允许对应 GitHub Pages 域名的 CORS 请求，不应提供任意 URL 转发。

## 本地运行

需要 Python 3，无第三方依赖：

```sh
python3 server.py
```

打开 `http://127.0.0.1:8766/`。本地服务仅监听回环地址，不向公网开放。

搜索的可播放检查使用独立静音音频元素，不会播放声音；无地址、加载失败、浏览器不能解码或超过检查时限的条目暂不显示。检查仅反映当前网络和音源状态，播放地址后续仍可能过期；只检查能否加载有效音频，不保证整首播放或排除平台试听。歌单导入保留平台列表，不因搜索筛选而丢弃歌曲。

导入检查会实际推进开头和中段的播放位置，并拒绝不足 45 秒的疑似试听地址；不能据此保证整首音频或原始母带质量。大歌单检查需要时间，请保持网页打开。导入指引和进度窗口打开时锁定背景滚动，关闭或按 Esc 恢复原滚动位置。关闭导入窗口可继续检查，刷新或关闭网页会中断未保存的检查；检查结束或点击停止后才合并保存，既有收藏不清空。文件本体不上传，检查及替换会向音乐接口发送歌曲 ID、歌名和歌手。

线上短链接解析服务的核心实现位于 `services/playlist-service.mjs`，由 Sites 的服务器端路由调用；GitHub Pages 只托管播放器前端，不能执行这个服务。服务只接受网易云 / QQ 域名，不提供任意网址转发，展开后仅向平台接口发送歌单 ID。

在线解析服务：https://liusheng-playlist-service.ivory-hinny-7935.chatgpt.site 。该服务已公开供播放器调用，接入时不需要在浏览器中配置认证令牌。
